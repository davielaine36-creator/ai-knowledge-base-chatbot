# AI Knowledge Base Chatbot

A polished, sellable demo of a **RAG (Retrieval-Augmented Generation) chatbot for service businesses**. It answers customer questions using **only** a business's own knowledge base — documents, FAQs, services, pricing, and policies — and shows the **sources** behind every answer.

The demo is themed around a fictional business, **Brown Academy**, a professional security training and requalification academy. Swap in any other business's documents and the assistant answers about them instead.

> Built with Next.js (App Router) + TypeScript + Tailwind CSS, with OpenAI for embeddings and chat. The vector index is a local JSON file — no database, no vector service, no accounts.

---

## What the demo does

- A clean landing page explaining the product, with a **live chat demo** embedded.
- A chatbot trained on local markdown knowledge files in `data/knowledge/`.
- A retrieval pipeline that:
  1. Embeds your question.
  2. Compares it against stored knowledge chunks (cosine similarity).
  3. Selects the most relevant chunks.
  4. Passes them to the AI to write a grounded answer.
- Strict answering rules:
  - Answers **only** from the retrieved knowledge base context.
  - If the answer isn't found, it says: _"I don't have that information in the current knowledge base."_
  - It does **not** invent prices, policies, dates, or requirements.
  - Every answer includes a **"Sources used"** section.

## Why a business would pay for it

- **Answers customers 24/7** — handles the routine questions your team answers every day.
- **Reduces repetitive enquiries** — fewer phone calls and emails for common questions.
- **Stays accurate and on-brand** — only uses approved content; never makes things up.
- **Builds trust** — shows sources, so customers (and you) can see where answers come from.
- **Easy to keep current** — edit a markdown file, regenerate, done.

It turns documents a business already has into a customer-facing assistant — a concrete, valuable deliverable for small service businesses.

## Run it locally

### 1. Prerequisites

- Node.js 18.18+ (Node 20+ recommended)
- An OpenAI API key — https://platform.openai.com/api-keys

### 2. Install dependencies

```bash
npm install
```

### 3. Set environment variables

```bash
cp .env.example .env.local
```

Then edit `.env.local` and add your key:

```bash
OPENAI_API_KEY=sk-your-key-here
# optional overrides:
# OPENAI_CHAT_MODEL=gpt-4o-mini
# OPENAI_EMBEDDING_MODEL=text-embedding-3-small
```

### 4. Generate the embeddings (vector index)

This reads `data/knowledge/*.md`, chunks the text, creates embeddings, and writes `data/vector-index.json`.

```bash
npm run embeddings
```

You must run this once before the chatbot can answer (and again whenever you change the knowledge base).

### 5. Start the app

```bash
npm run dev
```

Open http://localhost:3000 and try the chat demo.

## Adding or editing knowledge base files

The knowledge base is just markdown in `data/knowledge/`. Each file becomes a topic, and its filename becomes the friendly source name shown under "Sources used" (e.g. `pricing.md` → **Pricing**).

To customise the demo for a different business:

1. Edit, add, or remove markdown files in `data/knowledge/`.
   - Use clear headings (`#`, `##`) — chunks are split along headings, so good headings improve retrieval.
   - Keep facts explicit (prices, hours, policies) so the assistant can quote them accurately.
2. Update the on-screen copy in `src/app/page.tsx` and the assistant's persona in `src/lib/rag.ts` (the `SYSTEM_PROMPT`) if you change the business.
3. Regenerate the index (next section).

## Regenerating embeddings

Any time you change the markdown files (or switch embedding model), rebuild the index:

```bash
npm run embeddings
```

This overwrites `data/vector-index.json`. Restart `npm run dev` if it was running (the index is cached in memory).

## Deploying on Vercel

1. Push this repo to GitHub.
2. In [Vercel](https://vercel.com), **Add New → Project** and import the repo.
3. Add the environment variable `OPENAI_API_KEY` (and optionally the model overrides) in **Project → Settings → Environment Variables**.
4. **Important:** the vector index is git-ignored, so generate and commit it before deploying, **or** include it in the build. Two options:

   **Option A — commit the index (simplest):**
   ```bash
   npm run embeddings
   # then remove data/vector-index.json from .gitignore, commit it, and push
   ```

   **Option B — build it during deploy:**
   Add a build step that runs the embeddings script (requires `OPENAI_API_KEY` to be available at build time). For example, set the Vercel **Build Command** to:
   ```bash
   npm run embeddings && npm run build
   ```

5. Deploy. Vercel will give you a live URL you can share with prospects.

The `next.config.mjs` already includes `data/vector-index.json` in the serverless function bundle so the chat API can read it at runtime.

## How the chatbot stays grounded

- Retrieval only surfaces chunks above a similarity threshold (`MIN_SCORE` in `src/lib/config.ts`). If nothing relevant is found, the assistant returns the "I don't have that information" message instead of guessing.
- The system prompt forbids using outside knowledge and forbids inventing prices, policies, dates, or requirements.
- "Sources used" is derived from the actual retrieved chunks — not from the model — so it always reflects what the answer was built from.

## What to test before deploying

Run `npm run embeddings` then `npm run dev`, and check:

1. **Core questions answer correctly with sources:**
   - "What courses does Brown Academy offer?"
   - "How much is requalification?"
   - "What do I need to bring?"
   - "Can I get a refund?"
   - "How do I schedule a course?"
   - "Do you offer weekend classes?"
2. **Out-of-scope questions** (e.g. "What's the weather today?" or "Do you sell cars?") return _"I don't have that information in the current knowledge base."_ with **no** sources.
3. **No hallucinated specifics** — prices, dates, and policies in answers match the markdown files exactly.
4. **Sources are sensible** — the cited source files actually contain the answer.
5. **Error states are clean** — try with a missing/invalid `OPENAI_API_KEY` and before running `npm run embeddings`; the UI should show a helpful message, not crash.
6. **UI looks polished** on desktop and mobile widths.
